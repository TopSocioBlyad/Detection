# Detection — повторная идентификация дорожных ям

Магистерская курсовая «Детекция образов на основе сопоставления ключевых
точек изображения». Задача проекта — определить, изображена ли на двух
фотографиях одна и та же физическая дорожная яма, используя SIFT, ORB, AKAZE,
BRISK, сопоставление дескрипторов и RANSAC-гомографию.

Проект не решает задачу детекции произвольных ям, нейросетевой сегментации или
визуальной одометрии.

## Структура

- `data_reid/pothole_001 ... pothole_012` — 312 реальных кадров 12 вручную
  сгруппированных физических ям;
- `reid/` — новый воспроизводимый эксперимент повторной идентификации;
- `results/reid_audit` — manifest и аудит данных;
- `results/reid_pair_cv` — grouped cross-validation для проверки пар;
- `results/reid_gallery` — открытый gallery/query эксперимент;
- `legacy/` — исходники и результаты исторических этапов 1–7;
- `legacy/results/BASELINE.md` — описание зафиксированного baseline.

Названия папок `pothole_*` используются только для построения истинной
разметки, групповых разбиений и оценки. Функция сопоставления изображений не
получает `pothole_id`.

## Окружение

Проверенная версия Python — 3.12. Зависимости зафиксированы в
`legacy/requirements.txt`.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r legacy/requirements.txt
.venv/bin/python -m pip check
```

В облачной среде для графиков задайте доступный для записи кэш:

```bash
export MPLCONFIGDIR=/tmp/detection-matplotlib
```

## Воспроизведение

Команды выполняются из корня репозитория.

```bash
# Аудит данных и manifest.csv
.venv/bin/python reid/audit_dataset.py

# Pair verification: четыре фолда без пересечения физических ям
PYTHONPATH=. .venv/bin/python -m reid.evaluate_pairs

# Open-set gallery/query с ответом no_match
PYTHONPATH=. .venv/bin/python -m reid.evaluate_gallery

# Примеры RANSAC-инлайеров для верных и ошибочных решений
PYTHONPATH=. .venv/bin/python -m reid.visualize_examples

# Автоматические проверки
PYTHONPATH=. .venv/bin/python -m unittest discover -s tests -v
```

Скрипты оценки защищают основные результаты от случайной перезаписи. Для
намеренного повторного запуска в тот же каталог передайте `--overwrite`.

## Результаты реальных пар

В pair verification используются разные реальные файлы одной ручной группы,
а не синтетические преобразования одного RGB-кадра. Точные и близкие копии,
обнаруженные аудитом, исключены. Порог similarity score подбирается отдельно
в каждом фолде только на обучающих физических ямах.

| Метод | Precision | Recall | F1 | FAR/FPR | ROC-AUC | Average precision | Сопоставление, мс |
|---|---:|---:|---:|---:|---:|---:|---:|
| SIFT | 1.0000 | 0.9117 | 0.9538 | 0.0000 | 0.9601 | 0.9601 | 13.97 |
| ORB | 0.9968 | 0.8974 | 0.9445 | 0.0028 | 0.9526 | 0.9543 | 11.96 |
| AKAZE | 0.9970 | 0.9345 | 0.9647 | 0.0028 | 0.9712 | 0.9729 | 21.94 |
| BRISK | 1.0000 | 0.9288 | 0.9631 | 0.0000 | 0.9733 | 0.9744 | 21.46 |

Это 702 out-of-fold пары: 351 положительная и 351 отрицательная.

## Ограничения

У всех 312 файлов отсутствуют достоверные `capture_id` и исходные split в
именах. Большинство групп визуально состоит из близких кадров видеозаписи.
Поэтому метрики показывают работу на разных реальных кадрах, но не доказывают
устойчивость к независимой повторной съёмке в другое время или другим
устройством. Для такого вывода нужны подтверждённые отдельные сессии съёмки.

В `data_reid` нет масок, соответствующих этим кадрам. IoU не вычисляется и не
заменяется фиктивным значением. Старые высокие показатели из `legacy/results`
получены преимущественно на синтетических преобразованиях и не сравниваются с
новым экспериментом как равнозначные оценки.
