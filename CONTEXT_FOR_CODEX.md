# Контекст передачи проекта в облачный Codex

## Тема и постановка
Магистерская курсовая «Детекция образов на основе сопоставления ключевых точек изображения», направление «Мехатроника и робототехника, автономные роботы». Цель — повторно находить **ту же дорожную яму** в разных изображениях, несмотря на геометрические и фотометрические изменения. Не разрабатывать визуальную одометрию и не применять нейросетевые детекторы вместо ключевых точек.

## Данные и структура
Pothole-600, папки data/{training,validation,testing}/{rgb,label,tdisp}; RGB 400×400. Label — бинарная маска ямы; tdisp пока не используется. Разработка велась на Windows в VS Code, Python в .venv, скрипты в корне проекта.

## Этапы 1–5 (резюме предыдущего чата)
1. step01_pothole600.py: вырезание эталона по маске с padding, синтетическое преобразование, SIFT, BF, Lowe ratio. Пример testing/0050: 406 точек эталона, 2001 сцены, 198 соответствий после ratio.
2. step02_homography.py: RANSAC-гомография, перенос маски, IoU. Пример testing/0050: 198 инлайеров, ошибка репроекции 0.1173 px, IoU 0.9979. Это синтетическое преобразование одного кадра.
3. step03_batch.py: identity, rotate_20, rotate_60, scale_0.75, scale_1.25, perspective, darker, blur и отрицательная пара. Validation: 180 изображений, 1620 случаев, TP 1286, FP 2, FN 154, TN 178, F1 0.9428, IoU с отказами 0.887.
4. step04_compare.py: SIFT, ORB, AKAZE, BRISK, 11 положительных сценариев и одна отрицательная пара, 2160 случаев на метод. Validation: SIFT F1 0.85168 (76.8 ms); ORB 0.86108 (19.64 ms); AKAZE 0.14939 (34.28 ms); BRISK 0.82164 (27.43 ms). AKAZE выделял очень мало точек (медиана 4 в эталоне). Использовались Lowe 0.75, min_inliers 10, min_inlier_ratio 0.35, RANSAC 3 px, IoU threshold 0.5.
5. step05_parameter_tuning.py: фаза AKAZE threshold 0.001, 0.0005, 0.0001, 0.00005. На validation при 0.0001 F1 ~0.9682, время ~48.24 ms; при 0.00005 F1 ~0.9898, время ~811.31 ms (аномальный скачок, перепроверить). Фаза matching (Lowe ratio 0.65–0.85, min inliers 6/10/15/20): лучшие значения по выводу: SIFT F1 0.8832 ratio 0.7 inliers 6; ORB F1 0.8853 ratio 0.8 inliers 10; AKAZE F1 0.9916 ratio 0.8 inliers 6; BRISK F1 0.8589 ratio 0.85 inliers 6. Для AKAZE в фазе matching использовался threshold 0.0001. best_configs.json не обновился; восстановление возможно из matching_grid.csv через restore_step05_config.py.

## Методологические предосторожности
- Синтетические положительные пары зависимы и не равны реальным независимым съёмкам одной ямы.
- Pothole-600 может не содержать меток идентичности физической ямы; отрицательные пары не гарантированно разные физические ямы.
- Гомография приблизительна для неплоской ямы; контекст асфальта может доминировать в признаках.
- Метрики этапов 4 и 5 нельзя сравнивать напрямую без выравнивания сценариев.
- Проверить трактовку FP для ошибочной локализации положительной пары (может учитываться также FN).
- Не оптимизировать на testing.
