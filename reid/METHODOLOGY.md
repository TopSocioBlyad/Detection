# Методика эксперимента повторной идентификации

## Данные и аудит

`audit_dataset.py` рекурсивно проверяет все файлы `data_reid`, декодирует их,
фиксирует размеры и форматы, рассчитывает точные хэши пикселей с учётом
поворотов на 90° и перцептивные DCT-хэши для четырёх ориентаций.

Аудит обнаружил 312 читаемых PNG 400×400×3, шесть точных повторов и шесть
практически идентичных пар в `pothole_003`. Повторные экземпляры помечены в
`manifest.csv` и исключаются из экспериментов. После фильтрации остаётся 300
изображений.

`source_split` и `capture_id` имеют значение `unknown`: фактические числовые
имена файлов не позволяют достоверно восстановить эти метаданные. Название
папки используется как истинная физическая идентичность только при построении
пар и подсчёте метрик.

## Алгоритм сопоставления

Для каждого изображения один раз вычисляются признаки SIFT, ORB, AKAZE или
BRISK с параметрами из зафиксированного baseline этапа 5. Дескрипторы
сопоставляются BFMatcher KNN (`k=2`) и фильтруются тестом Lowe. По оставшимся
точкам оценивается RANSAC-гомография.

Гомография отклоняется, если она отсутствует, содержит нечисловые значения,
проецирует полный кадр в невыпуклый четырёхугольник или изменяет площадь более
чем в 20 раз либо менее чем до 5% исходной. Непрерывная оценка пары:

```text
similarity_score = ransac_inliers × inlier_ratio
```

Функция `verify_pair` получает только признаки двух изображений и параметры
метода. Идентификаторы ям и истинные метки ей не передаются.

## Pair verification

12 физических идентичностей делятся на четыре фолда по три ямы с балансировкой
числа кадров. В каждом фолде девять ям используются для настройки порога, три
другие — для итоговой оценки. Пересечения идентичностей нет.

Для каждой ямы выбирается до 30 положительных пар разных файлов. Из manifest
исключены точные и перцептивные копии. Отрицательных пар столько же, они
равномерно распределены по парам разных идентичностей. Порог выбирается по
максимальному F1 на обучающих идентичностях; при равенстве предпочитаются
меньший FPR и более высокий порог.

Итоговые показатели объединяют только out-of-fold решения. ROC-AUC и average
precision рассчитываются по непрерывному similarity score. FAR равен FPR.
Время `matching_ms` включает сопоставление и геометрическую проверку;
`cold_pair_ms` дополнительно включает извлечение признаков обоих кадров.

## Gallery/query и отказ

Каждый трёхидентичностный тестовый фолд образует три open-set эпизода. Одна
яма отсутствует в галерее, две другие представлены двумя эталонными файлами.
Все остальные кадры известных ям и все кадры отсутствующей ямы становятся
query. Score идентичности равен максимуму по её эталонам. Если лучший score
ниже порога pair verification, алгоритм отвечает `no_match`.

Измеряются rank-1 идентификация известных ям, false reject,
misidentification, correct rejection и false accept неизвестных ям. Эпизоды
коррелированы, потому что один query проверяется при нескольких составах
галереи.

## Ограничения интерпретации

Файлы являются реальными кадрами, но для них нет достоверных идентификаторов
сессий. По визуальному аудиту многие кадры соседние и сильно коррелированы.
Поэтому эксперимент проверяет сопоставление разных реальных файлов внутри
ручных групп, но не подтверждает повторное обнаружение после независимой
съёмки. Для более сильного вывода нужны несколько явно размеченных сессий для
каждой физической ямы.

Маски для `data_reid` отсутствуют, поэтому IoU не вычисляется. Контекст
асфальта занимает большую часть полного кадра и может вносить существенный
вклад в совпадения; это отдельная угроза валидности.
